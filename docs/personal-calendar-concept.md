# パーソナルカレンダー構想メモ

## 概要
会社・個人の予定を一元表示し、日常に必要な情報（天気など）も合わせて確認できる、自分専用の統合カレンダーダッシュボードを作成する。

## 必須要素

### 1. 会社の Google カレンダー連携
- Google アカウント（会社用）の予定を取得・表示
- Google Calendar API + OAuth2 認証を利用
- 取得範囲（当日/週/月）を選べるようにする

### 2. 個人の Outlook カレンダー連携
- 個人 Microsoft アカウントに紐づく Outlook の予定を取得・表示
- Microsoft Graph API + OAuth2（MSAL）を利用
- 会社カレンダーと合わせて「今日の全予定」として統合表示できるようにする

### 3. 天気・気温・湿度表示
- 現在地または指定地点の天気、気温、湿度を表示
- 天気API（例: OpenWeatherMap、気象庁API など）を利用
- 当日の予報に加え、時間帯ごとの推移や週間予報もあると便利

## 追加で検討すると良さそうな要素

- **予定の統合ビュー**: 会社・個人の予定を色分けして1つのタイムラインに表示（ダブルブッキング防止）
- **今日のToDo/タスクリスト**: 簡単なチェックリスト機能
- **通勤・交通情報**: 電車の遅延情報や移動時間の目安
- **服装・持ち物のアドバイス**: 天気や気温から傘・上着などの提案
- **祝日・記念日表示**: 日本の祝日や登録した記念日・誕生日のリマインド
- **ニュースヘッドライン**: 主要ニュースの見出しを数件表示
- **為替・株価ウィジェット**: 関心のある銘柄や為替レート
- **今日の一言/名言**: モチベーション用の一言表示
- **通知・リマインダー機能**: 予定の前に通知を送る
- **ダークモード対応**: 時間帯や好みに応じた配色切り替え
- **PWA化**: スマホのホーム画面に追加していつでも見られるようにする

## 技術的な検討事項（今後詰める）
- フロントエンド: React / Next.js など（PWA対応も考慮）
- 認証: Google OAuth2、Microsoft OAuth2（MSAL）をどう共存させるか
- バックエンド: 各APIの認証情報・トークンをどこで安全に管理するか（サーバーサイド推奨）
- ホスティング: 個人用途なら Vercel、Cloudflare Pages などの無料枠も選択肢
- データ更新頻度: 予定・天気それぞれのポーリング間隔
