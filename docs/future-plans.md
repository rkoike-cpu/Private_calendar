## 1. Outlook(個人アカウント)の未読メールチェック機能

### やりたいこと
個人のMicrosoftアカウントに紐づくOutlookの未読メール件数(または直近の送信者)を、ダッシュボードに表示する。

### 実現方法の方針
- Google Calendar連携と同様に、Microsoft Graph API(`https://graph.microsoft.com`)をOAuth経由で呼び出す
- 対象は**個人の**Microsoftアカウントのため、会社のGoogle Workspaceで直面したような「組織のセキュリティポリシーによる制限」は基本的に発生しない見込み
- 必要なスコープ: `Mail.Read`(読み取り専用)

### 事前準備の手順(Azure/Entraでのアプリ登録)
1. https://entra.microsoft.com にアクセスしてログイン
   - **注意**: `portal.azure.com` ではなく `entra.microsoft.com` を使うこと。前者はブラウザ環境(拡張機能・Cookie設定)に関わらず `AADSTS50058`(アクセストークン取得エラー)が頻発する不具合に遭遇した。`entra.microsoft.com` の方が安定していた
2. 左メニュー「アプリの登録」→「新規登録」
3. 設定内容:
   - 名前: 任意(例: `personal-calendar-outlook`)
   - サポートされているアカウントの種類: **「個人の Microsoft アカウントのみ」**
   - リダイレクト URI(プラットフォーム: Web):
     ```
     https://private-calendar-9ptj.onrender.com/auth/outlook/callback
     ```
4. 登録後、「アプリケーション (クライアント) ID」を控える
5. 「証明書とシークレット」からクライアントシークレットを発行する

### 現在の状況(ブロッカー)
アプリ登録を試みた際、Microsoft 365側で **サービス低下(service degradation)** が発生しており、Azure/Entraの管理画面でトークン取得エラーが頻発し、登録作業を完了できなかった。

- 障害状況の確認先: https://status.office365.com
- 「Resolved(解決済み)」になったら、上記手順から再開する

## 2. 複数ユーザー対応(社内の他の人も使えるようにする)

### やりたいこと
今は「自分専用」の設計だが、会社の同僚も自分のGoogleアカウントで同様に使えるようにする。

### 主な設計変更点
- **Google認証**: 今は「共有の認証情報を1件だけ」DBに保存する設計。これをユーザーごとに1件ずつ持つ形に変更する
  - ただし各自の会社アカウントも同じセキュリティポリシーの制約を受ける可能性が高いため、各自が「自分の会社PCなど信頼できる端末で1回だけGoogle認証する」という手順自体は今と変わらず必要になる見込み
- **ダッシュボードへのログイン**: 今は合言葉(`APP_PASSWORD`)1つを全員で共有しているが、ユーザーごとのアカウント(メールアドレス+パスワードなど)に変更する必要がある
- **データの分離**: ToDoリスト・予定の色分けカテゴリ・通知購読(push_subscriptions)などは今「アプリ全体で1件」のデータ構造になっているため、それぞれに「誰のものか」を表す列を追加し、ユーザーごとに分離する
